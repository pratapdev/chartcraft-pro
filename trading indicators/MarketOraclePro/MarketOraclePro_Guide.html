What is Market Oracle Pro?
🧠
Intelligence Layer
Combines 10 sub-systems — each measuring a different aspect of market structure — into a single Prime Score (0–10) and a live Market Bias readout.
🔊
Audio-DSP Filtering
Built around Ehlers' 2-pole Super Smoother, a low-pass filter borrowed from signal processing. Removes market noise with far less lag than EMA or SMA.
⚡
Auto Maximizer
Evaluates 4 candidate tuning lengths (10, 14, 20, 28) every bar over a 50-bar window. Automatically applies whichever maximises PnL or Win Rate.
📡
Market Prophecy
Projects a linear regression channel 12 bars into the future with 1.618-scaled deviation bands, giving a statistical view of next likely price range.

All 9 Sub-Systems
DSP FILTER
Ehlers Super Smoother
2-pole IIR (infinite impulse response) low-pass filter. Coefficients derived from pole angle and decay rate at the chosen cutoff period. Eliminates high-frequency noise while preserving trend inflections. Used as the primary oscillator backbone for all signals.
TREND LINE
Prime Trend Assistant
Supertrend-style adaptive S/R built on the slow Super Smoother + ATR envelope. Direction locks like a ratchet — only flips when price closes beyond the band. Acts as a dynamic trailing stop and bias filter. Green = bullish, Red = bearish.
BAND
Dynamic Reactor
An adaptive band built around the active Super Smoother baseline. In Volume Flex mode the band width scales with relative volume — widens on high volume, contracts on low. Supports MTF via timeframe input. Fill turns cyan/red to show trend direction at a glance.
S/R ZONES
Prime Ranges (VWAP)
Session-resetting VWAP with live ±1σ and ±2σ standard deviation bands. Computed from cumulative volume-weighted price variance — the true statistical distribution of price around fair value. ±2σ zones = high-probability reversal areas.
VOLATILITY
Momentum Wave Bands
Wide Bollinger-style envelope (EMA basis + 2.5σ) at the active tuning length. Touching the outer bands signals potential exhaustion. Band fill tracks trend direction. Basis line = dynamic mean-reversion reference.
PATTERN
Candlestick Structures
Three filtered patterns — Engulfing, Pin Bar, Star (3-candle). Each requires body size, range size, and volume to exceed moving averages. Labels appear below/above bar with pattern type code.
EXTREMES
Max Profit Signals ★
Pivot high/low detection (5-bar) validated by RSI divergence. Bearish divergence at HH → ★ top. Bullish divergence at LL → ★ bottom. Fires 5 bars after the pivot, once confirmation exists. Ideal for partial profit-taking or reversal entries.
PROJECTION
Market Prophecy
50-bar linear regression projected 12 bars forward. Slope determines direction. Deviation channels scaled by 1.618 (golden ratio) provide confidence range. Redraws on every bar — look at the current projection only, not historical ones.
CANDLES
Candle Coloring
Gradient: cyan/red with alpha tied to momentum strength — vivid = strong trend, faded = weak.
Classic: green/red OHLC.
Volume: vivid on above-avg volume bars, gray on low-vol bars.
Signal Types
◆ Buy (Trend Mode)
Fires when the fast Super Smoother crosses above the slow. Fast = tuning length. Slow = 2× tuning. The crossover is a low-lag proxy for momentum direction change, equivalent to a zero-lag MACD crossover but smoother. Works best on trending instruments.
◆ Sell (Trend Mode)
Fires when the fast Super Smoother crosses below the slow. Use this to enter short or exit long positions. In trending markets, signals are clean and infrequent. Higher tuning = fewer, stronger signals.
◆ Buy (Reversal Mode)
Stochastic crosses above 20 AND RSI is below 48. Both conditions must be true simultaneously — this confluence prevents firing in mid-trend dips and focuses on true oversold reversals.
◆ Sell (Reversal Mode)
Stochastic crosses below 80 AND RSI is above 52. Best used at VWAP ±2σ band touches or Momentum Wave Band extremes for maximum-probability reversal confluence.
★ Max Profit Top / Bottom
Gold star labels mark pivot divergence points. Top ★: price made new high but RSI didn't → trend exhaustion. Bottom ★: price made new low but RSI recovered → selling exhaustion. These are profit-taking zones or reversal entry zones, not primary signals.
Candlestick Structure Labels
E — ENGULFING
Current candle completely engulfs previous body. Body must exceed 10-bar average. Volume and range filters applied.
P — PIN BAR
Shadow is 2.5× the body and 2.5× the opposite shadow. Signals strong rejection of a price level. Volume filter required.
S — STAR
3-candle structure: strong candle → tiny indecision candle → reversal candle. Middle candle must be <45% of average body size.

Base period for the fast Super Smoother. Slow = 2×. Lower = more signals, higher noise. Higher = fewer, cleaner signals. Only used when Auto Maximizer is OFF.

Auto Maximizer
When ON, tests lengths 10, 14, 20, 28 every bar over 50-bar window. Picks the winner by PnL sum or Win Rate. Updates dynamically as market regime changes.
Default: ON
Optimize For
PnL: maximise total return from signals over window.
WinRate: maximise hit rate (% of profitable signals). Use PnL for trending markets, WinRate for ranging/choppy markets.
Default: PnL

Bug Fix Log

ROOT CAUSE — series int passed to ta.* built-ins

Pine Script's built-in functions like ta.atr(), ta.ema(), ta.rsi(), ta.stoch(), ta.linreg(), ta.stdev() all require a simple int for the length argument.

The original code computed eff_tuning as: auto_max ? optimal_tuning : tuning where optimal_tuning was derived from series booleans (pnl comparisons). This made the result a series int — a value that can change every bar. Pine cannot precompile the internal ring-buffer size for a series-length function call.

FIX 1 — Pre-compute at all 4 literal lengths

Instead of computing ta.atr(eff_tuning * 2) dynamically, we now compute all 4 candidate outputs up front using literal integers: ta.atr(20), ta.atr(28), ta.atr(40), ta.atr(56). The auto-maximizer only selects among these pre-computed series at runtime using a sel(v10, v14, v20, v28, vm) helper — no ternary with series int as a length.

FIX 2 — Manual tuning path preserved

When Auto Maximizer is OFF, tuning is used directly. Since tuning comes from input.int(), it is a simple int and is safe to use as a ta.* length argument. tuning * 2 is also simple int. All manual-mode calls use this path without wrapping in conditional logic.

FIX 3 — MTF request.security literal length

Inside request.security() the expression super_smoother(hlc3, rct_adj_len) used a series int. Fixed by using the literal 14 inside the security call, and applying volume-flex scaling only to the band width (ATR multiplier), not the smoother length.

FIX 4 — ta.change(time("D")) wrapped in nz()

On bar 0, ta.change() returns na. Comparing na != 0 evaluates to false in Pine which is correct, but wrapping in nz(..., 0) makes intent explicit and avoids potential edge cases on first bar session detection.

FIX 5 — Removed adaptive_len() function

The original adaptive_len(base) called ta.atr(base) with a series int base argument. This function was removed entirely. Its purpose (adapting length to volatility) is now handled implicitly by the Auto Maximizer's dynamic candidate selection across market regimes.

FIX 6 — color.new() in gradient mode

color.new(bull_col, grad_alpha) where grad_alpha is series int — this is valid since color.new() accepts series values. No change needed here, just confirmed it's safe. The switch on candle_mode correctly returns na for the "None" case which barcolor() accepts.

Quick Reference: Pine Type Rules
// ✅ SAFE — literal int ta.atr(14) ta.ema(close, 20) ta.rsi(close, 14) // ✅ SAFE — input.int() is simple int tuning = input.int(14, ...) ta.atr(tuning) // ok ta.atr(tuning * 2) // ok — simple * const = simple // ❌ FAILS — series int derived from conditionals eff_tuning = cond ? 14 : 20 // series int if cond is series ta.atr(eff_tuning) // ❌ ERROR // ✅ FIX — pre-compute, then select a14 = ta.atr(14) a20 = ta.atr(20) result = cond ? a14 : a20 // ✅ series float — ok // ✅ User-defined functions accept series int super_smoother(src, len) // ok — UDF has no ring-buffer constraint
